IASTAM · Problem 1 · Process or transmit?

Onboard Triage Console

A satellite flying Sentinel-2A's real orbit acquires far more data than it can send down to Toulouse. Every 30 seconds the value-aware engine decides, for each item onboard, whether to process it now, store it, transmit it or drop it, by pricing downlink, energy, GPU, CPU and storage and choosing the option with the best net value.

Method

How the engine decides

U(item, option) = E[value delivered] − λdownlink·MB − λenergy·Wh − λGPU·s − λCPU·s − λstorage·MB
option ∈ {process then send, send raw, keep}; λ raised until each resource's planned use fits its forecast supply
value

Estimate what each option is worth

Priority × probability the content is useful × decay with latency. Raw data waits for ground processing; a product keeps only part of the value but is far smaller.

price

Price the scarce resources

Forecasts of passes, eclipses and battery give each resource a supply. Prices rise until demand fits: zero when a resource is plentiful, high when it binds.

choose

Pick the best net option

Process now if a GPU/CPU slot, RAM and the battery reserve allow; otherwise store for later. Send in order of value per MB plus urgency.

guard

Protect the spacecraft

Keep free storage for incoming data and energy for the next eclipse and pass. Items that cannot reach the ground before their deadline are dropped.
